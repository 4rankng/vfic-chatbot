3Per-block field manual

For each block: what it does, how it fails, and the log/DB trace that proves the message reached it.

1Auth verifyBot HMAC compare_digest; OA x-zevent-signature. Unconfigured → 503.Secret mismatch with Zalo → silent 401 drop. NO row, NO turn. Only trace is bytes log.zalo webhook inbound bytes= in API logs. Absent = never hit endpoint.
2NormalizeParse event; only can_start_bot_turn text → turn. Receipts/follow/unfollow/button → side event.Non-text event routed away — by design, no turn. Misclassified text → no turn.Side events: handle_oa_side_event
3Dedup claimAtomic INSERT ON CONFLICT on (chat_id, msg_hash), 8s window.Zalo retry inside 8s → duplicate, intentionally dropped.status: duplicate / dedup table row
4record_inboundPersist WORKER message, bump version, unread++, opt-out scan, realtime event.Receipts must NOT bump version (would suppress in-flight reply).messages row with role WORKER + bumped conversations.version
5run_start_guardBOT → ok; SEMI_AUTO → ok after 5min human idle; HUMAN/CLOSED → starve.Bot silent but msg recorded = starved. Check conversations.bot_mode.No job enqueued; conv mode in DB
6acquire_lockConditional UPDATE bot_locked_until WHERE free. rowcount=1 wins.Already locked → status: locked. Stale lock after crash blocks new turns until TTL.status: locked / bot_locked_until column
7enqueueEnqueue to webhook_high. The worker owns a tracked native typing bridge during dependency setup (Bot only).Enqueue fail or depth > 40 → release lock + HTTP 503 (Zalo retries).503 / queue depth metric

6Diagnostic queries — run against the chatbot DB

Prod: docker compose exec postgres psql -U <user> <db> · Dev: host :5432. Replace :chat_id with conversations.zalo_chat_id (OA chats are oa:<external_id>). Keep two enums straight: messages.delivery_status = PENDING / SENT / FAILED / SUPPRESSED / DELIVERED / READ · bot_runs.outcome = SENT / SUPPRESSED / ERROR.

aConversation state — blocks 5, 6, 14

SELECT zalo_chat_id, zalo_channel, mode, status, version,
       bot_locked_until, taken_over_at, assigned_recruiter_id,
       last_inbound_at, last_outbound_at, unread_count, now()
FROM conversations
WHERE zalo_chat_id = :chat_id;

mode HUMAN/CLOSED = starved by guard (5). bot_locked_until in the future = locked or stale lock (6). taken_over_at set = a recruiter owns it (14).

bRecent messages — blocks 4, 9, 15, 16

SELECT id, sender, delivery_status, zalo_message_id,
       external_error, created_at
FROM messages
WHERE conversation_id = (SELECT id FROM conversations
                         WHERE zalo_chat_id = :chat_id)
ORDER BY created_at DESC LIMIT 12;

sender WORKER = user inbound (4), BOT = bot reply. delivery_status PENDING = stuck (9), FAILED = send error + see external_error (15), SUPPRESSED = ownership race (14).

cBot runs + per-stage timing — blocks 8, 12, 13, 15

SELECT id, version_at_start, outcome, started_at, ended_at,
       stage_timings->>'llm_ms'      AS llm_ms,
       stage_timings->>'safety_ms'   AS safety_ms,
       stage_timings->>'send_ms'     AS send_ms,
       stage_timings->>'outbound_adapter' AS outbound_adapter,
       stage_timings->>'outbound_prepare_ms' AS outbound_prepare_ms,
       stage_timings->>'outbound_provider_ms' AS outbound_provider_ms,
       stage_timings->>'outbound_provider_attempts' AS outbound_provider_attempts,
       stage_timings->>'outbound_retry_count' AS outbound_retry_count,
       stage_timings->>'outbound_retry_ms' AS outbound_retry_ms,
       stage_timings->>'outbound_refresh_count' AS outbound_refresh_count,
       stage_timings->>'outbound_refresh_ms' AS outbound_refresh_ms,
       stage_timings->>'outbound_chunk_count' AS outbound_chunk_count,
       stage_timings->>'outbound_result' AS outbound_result,
       stage_timings->>'total_ms'    AS total_ms,
       stage_timings->>'queue_depth' AS queue_depth
FROM bot_runs
WHERE conversation_id = (SELECT id FROM conversations
                         WHERE zalo_chat_id = :chat_id)
ORDER BY started_at DESC LIMIT 5;

outcome SENT / SUPPRESSED / ERROR. llm_ms dominates slow turns (12). The outbound_* fields are channel-neutral adapter metadata: they contain no message text, recipient ID, token, or provider envelope. outbound_provider_ms ends at the provider API response; it does not prove device rendering. If version_at_start < current conversations.version yet outcome = SENT, a stale reply may have slipped past the ownership guard (14).

dStuck-PENDING sweep + dedup — blocks 3, 9, ♻

-- stuck BOT replies older than 5 min (reconcile targets)
SELECT c.zalo_chat_id, c.bot_locked_until,
       m.id, m.delivery_status, m.created_at
FROM messages m
JOIN conversations c ON c.id = m.conversation_id
WHERE m.sender = 'BOT' AND m.delivery_status = 'PENDING'
  AND m.created_at < now() - interval '5 minutes';

-- dedup window for one chat
SELECT chat_id, msg_hash, created_at
FROM message_dedup
WHERE chat_id = :chat_id
ORDER BY created_at DESC LIMIT 10;
Read order for a silent bot: run (a) for mode/lock/version → (b) to see whether a BOT reply exists and its status → (c) to see how the last run ended and where the milliseconds went. That trio localizes most incidents without opening worker logs.
