================================================================================
VFIC miniCRM — Integration Quick Reference
How the website (miniCRM SPA) talks to n8n + Supabase. VFIC-specific. Scannable.
================================================================================

1. ARCHITECTURE AT A GLANCE
--------------------------------------------------------------------------------
Three actors, three hosts:

  Browser (recruiter)
      |
      |--> chat.tingting.vip         -> miniCRM SPA (static files, Caddy)
      |       |
      |       |--> Supabase JS client (https://vichwmxeptglqmzefsiq.supabase.co)
      |       \--> 1x webhook POST -> n8n (bot.tingting.vip)
      |
  n8n (bot.tingting.vip -> n8n:5678, Caddy reverse-proxy)
      \--> Supabase Postgres (Postgres node + Supabase vector-store node)

  - SPA:      miniCRM/app  (Vite + TypeScript, vanilla, @tabler/core UI)
  - n8n:      bot.tingting.vip  (also chat.tingting.vip/webhook/*)
  - Supabase: project vichwmxeptglqmzefsiq

Two integration channels from the website:
  (a) Website -> Supabase  : the @supabase/supabase-js client (all data + auth)
  (b) Website -> n8n       : ONE fetch() POST to a webhook (send human reply)


2. WEBSITE -> SUPABASE (the JS client)
--------------------------------------------------------------------------------
Client init:        miniCRM/app/src/supabase.ts  -> createClient(url, key, {auth...})
Config values:      miniCRM/app/src/config.ts (vficConfig)
Injected at runtime: window.__VFIC__ in miniCRM/app/index.html

  - supabaseUrl            = https://vichwmxeptglqmzefsiq.supabase.co
  - supabasePublishableKey = sb_publishable_...   (publishable/anon format)
      -> safe to ship to the browser; access is controlled by RLS, NOT key secrecy.

Auth (miniCRM/app/src/auth.ts):
  - supabase.auth.signInWithPassword({email,password})
  - supabase.auth.getSession() / signOut()
  - Gate: requireAdmin() reads profiles.role; must be 'admin' or redirect to login.

Tables READ (supabase.from(t).select):
  - conversations, leads, bot_runs, bridge_event_log, vfic_chat_histories, profiles

Tables WRITTEN:
  - leads         UPDATE  -> lead_stage, notes           (lead.ts)
  - conversations UPDATE  -> lead_id                     (inbox.ts)

RPCs (supabase.rpc):
  - vfic_take_over({p_zalo_chat_id, p_recruiter})  -> bot mode -> human, single owner
  - vfic_release  ({p_zalo_chat_id, p_recruiter})  -> human mode -> bot

Realtime:
  - channel on postgres_changes, table vfic_chat_histories,
    filter session_id=eq.<zalo>  -> live transcript refresh (conversation.ts)


3. WEBSITE -> n8n (one webhook POST)
--------------------------------------------------------------------------------
File: miniCRM/app/src/pages/conversation.ts
Only outbound HTTP call from the SPA. Sends recruiter's reply into Zalo via n8n.

  - URL     : https://bot.tingting.vip/webhook/vfic-human-reply
  - Method  : POST, header content-type: application/json
  - Payload : { zalo_chat_id, message, recruiter_id }
  - Handler : n8n workflow "VFIC Human Reply" -> Zalo OA send-message API


4. n8n -> SUPABASE (how workflows persist)
--------------------------------------------------------------------------------
Nodes used:
  - n8n-nodes-base.postgres                          cred "Postgres account"
  - @n8n/n8n-nodes-langchain.vectorStoreSupabase     cred "Supabase account"
  - @n8n/n8n-nodes-langchain.memoryPostgresChat      (chat memory)

Per workflow -> tables written:
  - VFIC Chatbot          -> conversations (upsert), bot_runs (audit),
                             vfic_message_dedup (idempotency),
                             vfic_chat_histories (LangChain Postgres memory)
  - VFIC Persist Lead     -> leads (upsert w/ COALESCE; auto lead_score)
  - VFIC Persist Memories -> memories (vector store, query match_memories)
  - VFIC Knowledge Ingest -> documents (vector store, query match_documents)


5. n8n INBOUND TRIGGERS (how external services reach n8n)
--------------------------------------------------------------------------------
  - Zalo OA webhook   -> VFIC Chatbot           (chat trigger)
  - Google Drive      -> VFIC Knowledge Ingest  (Drive trigger)
  - ExecuteWorkflowTrigger sub-workflows called by the main bot
      (Persist Lead, Persist Memories)

7. SECURITY NOTES
--------------------------------------------------------------------------------
  - RLS = admin-only via profiles.role='admin'. Frontend requireAdmin() is a UX
    complement, NOT the security gate -- the DB policy enforces access.
  - Publishable key is intentionally public; protection is RLS.
  - Ownership + version guard in the bot (conversations.mode/version) prevents
    bot and human replying at the same time during takeover.
  - GAP: the human-reply webhook currently has NO shared secret / signature
    check -- worth adding (header token or HMAC) before wider exposure.


8. DEPLOYMENT
--------------------------------------------------------------------------------
  - Docker Compose (miniCRM/ops/docker-compose.yml): n8n + Caddy + SPA files.
  - Caddy (miniCRM/ops/Caddyfile):
      chat.tingting.vip  -> static SPA;  /webhook/*  -> n8n:5678
      bot.tingting.vip   -> n8n:5678
  - SPA is built (Vite) to static files and served by Caddy file_server.
