# Zalo typing indicator — verification + implementation report (2026-09-30 22:40)

Task: wire the `TypingCapability` port (`app/channels/ports.py`) into a turn-start
call site and, if the official API exists, implement it for the Zalo OA adapter.

## Verdict

1. **Zalo OA has no officially documented typing / chat-status endpoint.** The
   candidate `chatstatus` / `chat_status: typing|clear` endpoint does **not**
   exist on `openapi.zalo.me`. Per the task's honesty rule, no endpoint was
   invented and the OA adapter was not modified.
2. **The call-site half already exists** — through a pre-existing, older seam
   than the registry: the graph's typing heartbeat. The requested feature
   ("typing shown at turn start until the reply goes out") is already
   implemented and working on the Zalo Bot channel, and is started (as a
   deliberate no-op) on the OA channel.
3. Adding the requested `registry.get_typing(...)` call site would be either a
   **duplicate pulse** (Bot: `ZaloBotChannelAdapter.send_typing` wraps the very
   same `ZaloBotSender.send_chat_action` the heartbeat already calls) or
   **dead code** (OA: `get_typing` returns `None` and there is no API to
   implement). Not done — KISS/DRY, and `runner.py` is a bug-magnet file.

## Doc verification result (required content)

- **Endpoint:** none found. `https://openapi.zalo.me` OA surface documents
  message sends (`/v2.0/oa/message`, `/v3.0/oa/message/cs`,
  `/v3.0/oa/message/transaction`), user/profile, webhook — no chat-status or
  typing operation. No `chat_status` request/response shape exists to record.
- **Method/payload:** n/a — nothing to call. (The Bot Platform API's
  `sendChatAction` is a different API surface, already wrapped by
  `app/services/zalo_bot_service.py::ZaloBotSender.send_chat_action`.)
- **Doc URLs checked (2026-09-30):**
  - https://developers.zalo.me/docs/api/official-account-api-230 (SPA; fetches render no body)
  - https://developers.zalo.me/sitemap.xml (no official-account doc routes listed)
  - https://stc-developers.zdn.vn/docs/v2/official-account/... (docs mirror: no chatstatus page)
  - Site-restricted searches over `developers.zalo.me` for `chatstatus` /
    `typing` / `"đang soạn"`: zero matches in the OA doc tree.
  - Community knowledge puts typing only on the **Bot Platform API** (already
    used here) and unofficial personal-account libraries (`zlapi`, `zca-js`) —
    not the OA OpenAPI.
- This independently re-confirms the repo's own prior conclusion, already
  encoded at `app/services/zalo_oa_service.py:439-446`
  ("OA OpenAPI has no Bot-Platform-compatible typing endpoint in this app's
  current contract" — logged no-op returning best-effort success) and the
  port docstrings in `app/channels/ports.py:54-64` /
  `app/channels/registry.py:63-71`. Those comments are accurate; no new code
  comment was added (would be redundant).

## What already implements the feature (verified, no changes needed)

- `app/services/webhook.py:262-263` — one-shot typing at webhook ack
  (`zalo_channel == "bot"`), DB-resolved live token.
- `app/workers/chatbot_worker.py:484-489` — `bridge_typing` pulses across the
  queue/build_deps preamble (bot only; OA correctly skipped).
- `app/graph/runner.py:329-340` — `_status_heartbeat` created at turn start for
  **both** `zalo_bot` and `zalo_oa`, first pulse immediate, cadence
  `settings.typing_heartbeat_seconds` (3.5s); OA pulses hit the logged no-op.
- `app/graph/dispatch.py:165-188` — heartbeat body; every pulse wrapped, failures
  logged at debug, never propagated.
- `app/graph/dispatch.py:252` + `app/graph/runner.py:792` — heartbeat cancelled
  before every real send, so the indicator stops on the answer (no manual
  "clear" needed; the Bot Platform action expires on its own and no OA clear
  API exists).
